# Claude Todos v4.1 Stability Design

## Scope

Fix v4.0 regressions without changing the approved v4 architecture: one multi-session backend daemon, one separate React client, global Settings, current+watched sessions, shared notifications and translation queue.

## Flow runtime stability

React Flow owns one mutable `nodes` state. Server/task updates are reconciled into that state only when graph semantics change. Layout persistence is read into a stable position map; saving a drag must not feed a changed layout object back into a graph-reconciliation effect. Programmatic `fitView`/`setViewport` operations are guarded so their `onMoveEnd` callback does not immediately persist and re-trigger restore work. The goal is to eliminate the maximum update-depth loop while preserving draggable persisted positions and multi-session lanes.

## Sessions registry performance

`SessionRegistry` keeps an in-memory metadata cache keyed by transcript path and stat signature `(mtime_ns, size)`. Discovery stats every JSONL file but re-parses only new or changed files. `/api/sessions` returns the current in-memory registry snapshot and never triggers a full transcript scan. A new explicit `POST /api/sessions/refresh` performs discovery on demand. The daemon watcher continues background discovery every five seconds using the stat cache.

Session counters are read from lightweight cache indexes/files only. Listing sessions must not instantiate every child runtime. Translation aggregation similarly reads persisted translation-job files from disk for inactive sessions; a child runtime is created only for current/watched sessions or an explicit action that requires it.

## Client bootstrap / splash

AppProvider exposes a bootstrap lifecycle: `loading`, `ready`, `error`. Startup fetches the minimum shell-critical data first: sessions snapshot, current-session state, global settings, prompts. The app renders a full-screen branded splash until these are ready and the lazy route module is available. Heavy cross-session translation/history data loads after shell readiness and refreshes independently. On bootstrap failure the splash shows a concrete error and Retry.

## Sessions interactions

The Sessions table puts `Current` and sticky `Action` columns next to the left-side watch/current controls, so Switch is always visible without horizontal scrolling. Switch is optimistic: client app-state changes immediately, then the backend request confirms or rolls back on error. Single-click is the only interaction; rows do not have double-click behavior.

Each session row contains its own EN/HU switch. Changing a non-watched session's language automatically enables watch first. The header no longer contains global EN/HU. Session language remains session-specific; Settings remains fully global.

## Header layout

Header order: connection dot + brand, responsive current-session button, flexible spacer, navigation, history bell. Navigation is right aligned. Session button width uses a responsive clamp so more label/project context remains visible on wide screens.

## Task language badges

Task references display a compact language badge derived from task/session state:
- `🌐 HU` current task wants HU and renders HU
- `⏳ HU` wants HU but current translation is pending/missing
- `⚠ HU` wants HU but current translation failed
- `✓ HU cached` task currently renders EN but current fingerprint has a valid HU cache
- `EN override` task renders EN while its session global language is HU

The badge is reused on Tasks cards, Flow nodes, task drawer header, dependency labels, notification/history task references, and Translation parent rows where practical.

## Testing

Add regression tests for:
- Flow semantic reconciliation does not rewrite nodes for position-only/layout persistence updates.
- programmatic viewport restore is guarded from persistence feedback.
- `/api/sessions` does not call transcript discovery.
- unchanged transcripts are not re-parsed across refreshes.
- translation/session listing does not instantiate inactive runtimes.
- session Switch action is visible/sticky and optimistic.
- splash remains until critical bootstrap is ready and exposes Retry on error.
- session language switch auto-watches an unwatched session.
- header has no global language control and nav is right aligned.
- task language badge classifications.
