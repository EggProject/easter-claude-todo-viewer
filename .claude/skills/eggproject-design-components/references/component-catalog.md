### card

Owned by B / components — [`../components/card/Card.jsx`](../components/card/Card.jsx), [`../components/card/card.css`](../components/card/card.css), canonical **static HTML** demo [`../components/card/card.html`](../components/card/card.html). One **React** component `Card` — browser-global `Object.assign(window, { Card })` → `window.Card`, **no** ESM/CJS, **no** IIFE, **no** auto-init, **no** TS, **no** `CardHeader`/`CardBody`/`CardFooter`/`CardActions`/`StatCard`/`MetricCard` helper. Passive surface / content container; distinct from and **not** a consumer of the closed **EmptyState** `.empty--card`, the **DataTable**/**TradeTable** wrappers, the **Dialog**/**Drawer** surfaces, the **hover-card** family (name collision only) or the `.card-select` CSS primitive. `Card({ feature, title, icon, meta, children, className = '', ...rest })` — `feature` boolean → `.card--feature` dark/featured modifier; `title` string → **real `<h3>`** in `.card__header`; `icon` string|ReactNode → **decorative** `.card__icn` mark; `meta` `[left, right]` tuple → two real `<span>`s in `.card__meta`; `children` body → **real `<p>`**; `className`/`...rest` root-`<div>` passthrough; no state; **passive / non-interactive root**. **No** `heading`/`headingLevel`/`as`/`description`/`eyebrow`/`media`/`footer`/`actions`/`href`/`onClick`/`role`/`variant`/`tone`/`size`/`elevated`/`interactive`/`selected`/`disabled`/`ariaLabel`/`ariaLabelledby`/`ariaDescribedby` prop, **no** TS, **no** subcomponent. **Text-first accessibility**: meaning carried by real, unhidden DOM text (`<h3>` title + `<p>` body + meta `<span>`s); root is a passive `<div>` with **no** false `role="button"`/`role="link"`/`role="region"`/`role="article"`/`role="img"`, **no** `aria-live`/live region; **not** a whole-card link. **Decorative icon**: when `icon` is truthy `.card__icn` always carries **`aria-hidden="true"`** (decorative initial/SVG, skipped by AT, no exclusive meaning); **no** informative-icon/media API (`role="img"`/`aria-label`). **No built-in CTA / href / onClick / actions / footer / interactive API** — an interactive card or CTA is consumer-supplied native `<button>`/`<a>` inside `children` (the closed Buttons family owns that), avoiding whole-card-link + nested-interactive. `@media (forced-colors: active)` **system-colors-only** (no token/hex/rgb/hsl, no `forced-color-adjust:none`): `.card` + `.card--feature` `Canvas`+`CanvasText`+`1px CanvasText` border+`box-shadow:none` (replacing the feature card's normal `border:none`, closing HCM contour loss), `.card h3`/`.card p` `CanvasText`, `.card__meta` `GrayText`, `.card__icn`/`.card--feature .card__icn` `ButtonFace`+`CanvasText`+`CanvasText` border; `.card__header` layout wrapper gets no rule; **live emulation not run (CSSOM-only, P2)**. **No motion**: no `transition`/`animation`/`@keyframes`, **`transition: all` = 0**, no reduced-motion guard needed. Classes `.card`(`--feature`)`/.card__header/__icn/__meta`, `.card h3`, `.card p` — all active classes have CSS, no dead selector, no source↔CSS↔demo drift; invalid `feature`/`meta` does not crash (fixed `[left, right]` tuple is an API limit). **Static canonical demo** shows a default + a `.card--feature` card (header/icon/title/body/meta; no interactive/CTA/stat example); React `<Card>` not demoed — the React component + class contract are the recommended source. **No active React consumer** — `<Card>`/`window.Card` unused; the `.card`/`.card__*` classes are consumed as static markup across app-common shells, web-examples (index/not-found), admin-examples (index/settings), the components demos index and design-preview pages; `styles.css` aggregation only; `SKILL.md` registry (`Card | card | Card`); `components/README.md` `card | Card | CSS` mislabel tracked as drift; **blast radius low for the React component, high for the `.card`/`.card__*` CSS contract**. P3: `.card--feature .card__icn` hardcoded rgba in normal CSS, `components/README.md` classification drift, fixed `<h3>` heading level (no `headingLevel`/`as`), demo-only two static examples. Status: **P0/P1 closed; P2/P3 documented.** See DESIGN.md → "Cards / Containers".

### charts
Custom **inline-SVG** data-viz components — `LineChart` and `BarChart`. No external charting lib (hand-rolled SVG
paths/rects); **not** an `LcWrap` / `lightweight-charts` wrapper. Sources
[`../components/charts/LineChart.jsx`](../components/charts/LineChart.jsx),
[`../components/charts/BarChart.jsx`](../components/charts/BarChart.jsx); CSS
[`../components/charts/charts.css`](../components/charts/charts.css); canonical React demos
[`../components/charts/charts.html`](../components/charts/charts.html) (one Bar + one Line),
[`../components/charts/linechart.html`](../components/charts/linechart.html),
[`../components/charts/barchart.html`](../components/charts/barchart.html). Browser-global exports `window.LineChart` /
`window.BarChart` (IIFE, `Object.assign(window, …)`); **no** ESM/CJS, **no** auto-init. `function LineChart()` /
`function BarChart()` take **zero props** — all data is **hardcoded sample data** (LineChart `LC_SERIES` + `LC_MONTHS`,
3 series × 12 months; BarChart `CATEGORIES` + `COLUMNS_DATA`, 4 categories × 9 quarters), all state internal
(`hoverIndex` / `hiddenKeys` / `mounted`); no `data`/`labels`/`series`/`className`/`style` API, no TS type. **SVG text
alternative**: each main `.line-chart-svg` / `.bar-chart-svg` has `role="img"` + `aria-labelledby` → per-instance
`useId()` `<title>` (short name) + `<desc>` (**data-driven summary** — series/category, time range, latest values,
trend %, min/max), so multi-instance ids never collide and the desc updates on **legend-toggle** (native `<button>`
`.line-chart-legend-item` / `.bar-chart-legend-item`, hides via `hiddenKeys` + `.is-off`). **Pointer-tooltip boundary**:
the per-point/per-quarter tooltip is **hover-only**; the `<desc>` summary is the non-visual alternative — full
keyboard-tooltip / focusable data-point grid / complete `sr-only` table are **P2** follow-ups (do not claim them).
**reduced-motion**: `@media (prefers-reduced-motion: reduce)` disables line-draw/bar-grow/tooltip-fade and pins final
state (line fully drawn, bar `scaleY(1)`); **`transition: all` = 0**. **forced-colors**: `@media (forced-colors:
active)`, system colors only (no token/hex/rgb/hsl, no `forced-color-adjust: none`), line series differentiated by
**dash** (`--0` solid / `--1` `7 4` / `--2` `2 3`) + bar outline + legend + desc — **live emulation not run
(CSSOM-only, P2)**. **focus-visible**: `.line-chart-legend-item:focus-visible` / `.bar-chart-legend-item:focus-visible`
→ `box-shadow: var(--ep-shadow-focus)`, forced-colors `Highlight` fallback; no bare `:focus`, no focus `!important`.
Normal-mode hardcoded SVG hex sample colours kept (not a token migration) — **P2/P3**. `charts.css` pre-existing global
reset leak = **P2**. Root class `.line-chart-wrapper` **collides by name** with the closed `LcWrap` root class, but
`charts.css` is scoped and does not reopen `LcWrap` — **P3**. **No active consumer** (demo + registry only); low blast
radius. Status: React **P0/P1 = 0** (SVG text-alternative + pointer-only-data P1s closed at summary level); P2/P3
documented. See DESIGN.md → "Charts".

### data-table
Owned by B / components — `../components/data-table/` (`DataTable.jsx`, `datatable.css`, `data-table.html`). A
**DataTable-shaped showcase** on **TanStack React Table** (`window.ReactTable`, read lazily) — **not** a generic,
prop-driven reusable table, **not** an ARIA grid, **not** a native `<table>`, and **not** the admin `InvoiceTable
island`. Browser-only `window.DataTable`; `function DataTable()` takes **no props** — data (fixed `ROWS`, 18 items),
columns (fixed 9: select/ID/Project/Owner/Status/Priority/Hours/Updated/Actions) and all state are internal (no
external `rows`/`columns`/`data`/callback API, no controlled sorting/selection). `getRowId: row => row.id` →
stable `AT-*`/`NB-*` keys. Standalone demo `../components/data-table/data-table.html` bootstraps vendored
React/ReactDOM/Babel + TanStack + the design-system `Tooltip` (`window.Tooltip`); one React root, no auto-init.
**Div-based ARIA table**: `role="table"` `aria-label="Projects"` → three `role="rowgroup"` (header + pinned body +
center body) → `role="row"` → `role="columnheader"`/`role="cell"`; the header rowgroup (`.data-table__header-group`)
uses `display: contents` so the sticky header is preserved. **Sorting** via `getSortedRowModel` over internal
`sorting` (initial `hours desc`) + a Priority custom `sortingFn`; sortable columnheaders are keyboard-reachable
(`tabindex="0"`, pointer + Enter/Space with `preventDefault`) exposing `aria-sort` `ascending`/`descending`/`none`
(removal supported); select/Updated/Actions are not sortable (no `tabindex`/`aria-sort`). **Selection**: custom
`<button role="checkbox">` with `aria-checked` `true`/`mixed`/`false`; every checkbox is named — select-all `Select
all projects`, rows `Select project <id> <project>` (unique, stable-id bound), column visibility `Toggle column
<name>`, filters `Filter owner <name>` / `Filter <column> <option>` / `<column> filter: <placeholder>` / `<Min|Max|
Equals> hours filter`; a checkbox click never sorts or opens row inspect; selection survives sort/pagination.
`.data-table-checkbox` (+ `--on/--partial`) is the **canonical checkbox styling origin** (TradeTable only mirrors it
locally; DataTable does not import TradeTable CSS), with a `:focus-visible` `--ep-shadow-focus` ring + forced-colors
`Highlight` fallback; the sortable-header `:focus-visible` uses an inset accent/ink ring (+ forced-colors fallback).
**Filtering** (global search + per-column text/select/priority-multi/owner-autocomplete/hours-min-max-eq/updated-
range, empty `No projects match your filters.`), **pagination** (page size 5/7/12/20, prev/next, range + page
count), and **pinning/resize/reorder/visibility** (row + column pinning, sticky header/filter/pinned rows,
horizontal scroll, native drag reorder, edge resize) round out the showcase. Root class is `.data-table-wrapper`
(height-resizable; no `.data-table-shell`/`.data-table-card`). Row inspect (`.is-active` + footer `Row open: <id> ·
<project>`) is pointer-only; the bulk bar's Assign/Archive/Delete are inert demo stubs (Clear works). The separate
non-consumer `../../eggproject-design-admin-app-examples/examples/billing-invoices.jsx` (`InvoiceTable island`, native
`<table>`) reuses `datatable.css` but does **not** consume `window.DataTable`. Status: **P0/P1 closed**; documented
P2 (browser-only export, no prop API, fixed internal data/columns, no active app consumer, pointer-only row inspect,
limited keyboard reach for drag/reorder/resize/pin, no loading/error/live-region, horizontal-scroll-only responsive,
no dark/ink variant, incomplete forced-colors coverage, live forced-colors emulation not run, missing reduced-motion
guard on some paths, hardcoded status/avatar colors) + P3 (hardcoded `en-US`/“ago”, inert bulk actions). See
DESIGN.md → “DataTable”.

### tabs
Tabs family — three React exports: `UnderlineTabs` (in-page **Tabs**), `Segmented` and `Pills` (each a
**single-select horizontal radiogroup**, not Tabs / navigation / multi-select). Classes `.tabs`, `.seg`,
`.pills`. Shared public prop core `items`, `active`, `onChange`, plus optional `aria-label` /
`aria-labelledby` for the accessible group name. **UnderlineTabs item** `{ id, label, count?, content? }`
(missing `content` → empty but valid panel); **Segmented / Pills items** are bare strings or
`{ id, label }` (string → id = label = the string). **Controlled** when `active != null`, else
**uncontrolled** with a first-item fallback (the fallback never calls `onChange`; re-activating the
current item is a no-op; another item fires `onChange(nextId)` once). UnderlineTabs renders `.tabs-root`
→ `.tabs` `role="tablist"` (native `<button type="button" role="tab">` + `aria-selected` + roving
`tabIndex` + stable `React.useId()` id + `aria-controls`) → `.tabs__panels` → `.tabs__panel`
`role="tabpanel"` + `aria-labelledby` + `hidden` while inactive (all panels stay mounted, so child /
input state survives). Segmented / Pills render `role="radiogroup"` → `role="radio"` + `aria-checked` +
`.is-on` + roving `tabIndex`. Keyboard: Tabs use `←` / `→` / `Home` / `End` (looping, automatic
activation, RTL-aware, no `↑` / `↓`); radiogroups use the standard `←` / `→` / `↑` / `↓` / `Home` / `End`
map with selection-follows-focus. All triggers are native `type="button"` (selecting never submits a
form). Focus-visible is the `--ep-shadow-focus` ring (forced-colors → `Highlight` outline); forced-colors
maps selected / checked to a real `Highlight` underline / surface; reduced-motion drops the color
transitions. Responsive: `.tabs` stays one row and scrolls horizontally (`max-width: 100%`, no wrap / no
ellipsis); `.pills` wraps; `.seg` is a compact inline row. **P2 / limits:** the scrollable `.tabs` can
edge-clip the normal outset focus ring (the forced-colors outline is not clipped); browser-only `window`
exports; no `disabled` / `activationMode` / `orientation` / vertical / multi-select / compound
`TabsList` / `TabsTrigger` / `TabsContent` API; no runtime id validation; Pills is single-select.
**Static integration status:** the static `pricing` / `inbox` / `analytics` `.seg` markup is an
accessible page-local single-select radiogroup (native `button[type="button"]`, `role="radiogroup"` /
`role="radio"`, an accessible group name, `aria-checked`, roving `tabIndex`, `←` / `→` / `↑` / `↓` /
`Home` / `End` with selection-follows-focus); the `settings` `.tabs` markup is native link-based section
navigation (`<nav class="tabs">`, real fragment links, an accessible nav name, `aria-current="location"`,
natural link + modifier-click behavior). These static consumers reach behavioral / accessibility parity
through their own page-local recipe rather than rendering the React `Segmented` / `UnderlineTabs` exports
directly — an accepted integration limit (P2), not a pending migration. Standalone demo:
`components/tabs/tabs.html`. See DESIGN.md → "Tabs" and "Segmented and Pills".

### select
Select family — two React exports: `Select` (a **button-based, select-only combobox**) and `Combobox` (a
**searchable select** / autocomplete-list). Not a native `<select>`, freeform input, creatable, tags,
multi-select or navigation menu. **Option item** (both): `{ value, label, icon?, meta?, disabled? }` —
object-only, `value` is the selection identity + callback value. **`Select`** `({ options, value, onChange,
placeholder, size ('sm'|'md'), icon, align ('left'|'right'), className, id, ...rest })` is **controlled-only**
(no `defaultValue` / uncontrolled, no root `disabled`, no `name` / form value); the trigger is `<button
type="button" role="combobox" aria-haspopup="listbox" aria-expanded aria-controls aria-activedescendant>` over
an **always-mounted** `role="listbox"` panel that is `hidden` when closed (`.menu[hidden] { display:none }`
removes it from layout + a11y tree; options stay in the DOM — no `aria-hidden` / `inert` / unmount).
**`Combobox`** `({ options, value, onChange, placeholder, className, disabled, name, id, aria-* })` has
**controlled selection** plus internal `query` / `open` / `activeIndex` state; the input is `role="combobox"` +
`aria-autocomplete="list"` over a **conditionally-mounted** `role="listbox"` (present only while open);
label-based case-insensitive filtering with a **"No matches"** empty state, query is never a selection value.
**Keyboard differs:** Select — Enter/Space/↓/↑ open, ↓/↑/Home/End move, Enter/Space select, Esc closes +
refocuses, no typeahead, manual activation (not selection-follows-focus); Combobox — type to filter, ↓/↑ move,
Enter selects the active option (none active → native submit possible), Esc/Tab close, Home/End keep the text
caret, IME-safe. **Accessible name is the consumer's responsibility** (Select via `aria-label` /
`aria-labelledby`; Combobox via a visible `<label htmlFor>` / `aria-label` / `aria-labelledby`) — a selected
label / placeholder is not a name. **Form:** Select is UI-only (no `name` / hidden input / `required`);
Combobox with a `name` renders a hidden input carrying the selection `value` (not label / query), `disabled` →
excluded from `FormData`; neither fully honours a native form reset under controlled state. **Focus:** Select
trigger + native `select.select` use `:focus-visible`, Combobox input uses `:focus`; normal ring
`var(--ep-shadow-focus)`; forced-colors gives a real `Highlight` outline and `menu.css` system colors
(Canvas/CanvasText, Highlight/HighlightText, GrayText), no `forced-color-adjust:none`; reduced-motion drops
the caret rotation + panel-entrance animation. **Native static consumers** (`onboarding.html`,
`settings.html`) intentionally use native `<select class="select">` / `.select--sm` (visible `<label for>`,
native `name` / `<option selected>`, platform keyboard/pointer/touch, no custom ARIA, no popup JS) — **not**
React `Select`; the `settings` `<nav class="tabs">` is separate closed link-navigation. Classes: `.select`,
`button.select`, `select.select`, `.select__value` (`.select__value--placeholder`), `.select__caret`,
`.select__panel`, `.select--sm`, `.select--open`; `.combo`, `.combo__input`, `.combo__caret`, `.combo__panel`,
`.combo__empty`; shared `.menu` / `.menu__item`. **P2 / limits:** Select re-selecting the current value still
fires `onChange`, no typeahead, no runtime option-shape validation; Combobox searchable-select only (not
freeform), no `required`; browser-only `window` exports. Standalone demo: `components/select/select.html`.
See DESIGN.md → "Select" and "Combobox".

### breadcrumb
Breadcrumb — one React export: `Breadcrumb`, a **hierarchical page-structure navigation** (root → current
page). Not Tabs, a stepper, pagination, history, a menu, a progress indicator or a route-switcher. **Signature**
`Breadcrumb({ items = [], separator = 'slash', maxItems = 6, className = '' })`; `separator` ∈ `'slash'`
(default) / `'chevron'` / `'dot'`. **Item** (object-only) `{ label, href?, icon?, onClick? }` — `label` visible
text, `href` the real ancestor target, `icon` optional decorative node, `onClick` optional link passthrough;
**no** scalar item, `current` field, `id`, per-item separator, disabled item or runtime item validation.
**Implicit current:** the **last displayed item** is the current page (implicit, no `current` field) — a
non-interactive `<span class="breadcrumb__item breadcrumb__item--current" aria-current="page">`, exactly one
whenever ≥1 item renders, out of the Tab order; a single item is that current span (no link / separator); an
empty `items` renders an empty but named `<nav aria-label="Breadcrumb">` without throwing. **Root** is a native
`<nav aria-label="Breadcrumb">` landmark (no redundant `role`; fixed name, no `aria-label` / `aria-labelledby`
override, so several on one page share the landmark name). **Flat DOM** — items + separators directly under the
nav, **no** `<ol>` / `<ul>` / `<li>`. **Ancestor links** are native `<a>` (missing `href` → `#` fallback, so
supply a real one); modifier-click, new tab, context menu and Tab / Enter stay native; `onClick` passes through
and the component never calls `preventDefault`; no router integration. **Separators** `.breadcrumb__separator` +
variant class, `aria-hidden="true"`, not focusable, never after the current item — chevron is the component's
own `focusable="false"` SVG, dot is a CSS pseudo-element; no consumer separator node. **Collapse** past
`maxItems` (default 6) keeps the first + trailing + current items and collapses the middle into a
**non-interactive** `<span class="breadcrumb__more" aria-hidden="true">…</span>` (not a button / disclosure /
popup / menu, not focusable, no `onMore` / `expandable`, no interactive overflow disclosure). **Keyboard** is
the native link model — Tab / Shift+Tab / Enter, current + ellipsis not focusable; no Arrow / Home / End, no
roving tabindex, no own keyboard listener. **Focus-visible** `.breadcrumb__item[href]:focus-visible` →
`box-shadow: var(--ep-shadow-focus)` (navigable links only, not the current span). **Forced-colors** → real
`outline: 2px solid Highlight; outline-offset: 2px; box-shadow: none` (no `forced-color-adjust: none`, no
`!important`; current stays distinct via font-weight). **Reduced-motion** drops the item `color` /
`background-color` transition (no `transition: all`, no animation). Classes: `.breadcrumb`, `.breadcrumb__item`,
`.breadcrumb__item--current`, `.breadcrumb__separator` (`--slash` / `--chevron` / `--dot`), `.breadcrumb__more`,
`.breadcrumb__icon`. **Static consumers** — `analytics.html`, `billing.html`, `shell-sidebar.html`,
`shell-topnav.html`, `docs.html` — each a native `<nav class="breadcrumb" aria-label="Breadcrumb">` with
`.breadcrumb__item` links, a `.breadcrumb__item--current` span + `aria-current="page"`, the shared
`breadcrumb.css`, and no page-local keyboard or popup / state (their placeholder `href="#"` links are demo /
skeleton limits to swap for real routes, **not** React `Breadcrumb` instances). **P2 / limits:** browser-only
`window` export; root accessible name not overridable; no `<ol>` / `<li>` semantics; implicit current; no
runtime item validation; missing `href` → `#` fallback; no interactive overflow disclosure; no router
integration; long-label / separator wrapping subtleties; static skeleton hrefs are placeholders. Standalone
demo: `components/breadcrumb/breadcrumb.html`. See DESIGN.md → "Breadcrumb".

### nav
Pill-style marketing top bar (`TopNav`), owned by B / components (`../components/nav/TopNav.jsx`, `../components/nav/nav.css`,
canonical demo `../components/nav/nav.html`). Browser-global `window.TopNav` (`Object.assign(window, { TopNav })`) — **no**
ESM/CJS, **no** auto-init. API: `function TopNav({ brand, links = [], activeId, onSelect, actions })` — `brand` = `{ src, label }`,
`links` = `[{ id, label, href? }]`, `activeId`, `onSelect(id)`, `actions` (ReactNode); links + active state are parent-controlled,
only the mobile-sheet `open` flag is internal; **no** `items` / `logo` / `active` / `current` / `onNavigate` / `className` / `style` /
`children` / `...rest` / TS type / public id or label prop. **Disclosure navigation, not an ARIA menu widget:** desktop + mobile
links are native `<a href>`, the sheet has **no** `role="menu"` and its links **no** `role="menuitem"`, **no** roving tabindex /
`aria-activedescendant` / Arrow-Home-End menu handling; Tab walks the open sheet, Enter activates natively, the closed sheet is
`display:none` (not focusable). Root is `<nav aria-label="Primary navigation">`. **Toggle:** native `<button type="button">` named
`Open menu` / `Close menu`, `aria-expanded` from `open`, `aria-controls` → sheet id from `useId()` (instance-unique, not public);
**Escape** closes the open sheet + returns focus to the toggle (closed Escape is a no-op), no focus trap / overlay / scroll-lock.
Active link gets `is-on` + `aria-current="page"` (desktop + sheet). `:focus-visible` = `var(--ep-shadow-focus)` on toggle + links
(action-slot buttons keep the Button family's own focus, P2); local `@media (forced-colors: active)` — system colors only, no
token/hex/rgb/hsl, no `forced-color-adjust: none` — **CSSOM/source-verified only**. **No motion**: `nav.css` has no `transition` /
`animation`, `transition: all` = 0, so no reduced-motion block is needed. Classes `.topnav` (`.is-open`), `.topnav__brand`,
`.topnav__links` (`a.is-on`), `.topnav__actions`, `.topnav__toggle`, `.topnav__sheet` (`a`, `a.is-on`), `.topnav__sheet-actions`,
`.topnav__sheet hr`. Canonical demo is a **static HTML mock** (no React/ReactDOM/Babel/`TopNav.jsx`, `window.TopNav` absent, vanilla
toggle script) that may still carry the old `role="menu"` / `role="menuitem"` markup + fixed `topnav-sheet` id — React↔demo drift,
non-blocking P2/P3. **No active app consumer** (marketing-site's own `TopNav` is a separate `.ep-topnav` duplicate-by-name, not a
consumer); demo-only, low blast radius. Status: **React P0/P1 closed; P2/P3 documented.** See DESIGN.md → "TopNav".

### toast
Babel-mounted notification primitives — three exports: `useToasts()` → `{ toasts, push, dismiss }`,
`ToastViewport` and the presentational `Toast`. `push({ title, message, variant, meta, duration,
action })` appends a toast and returns a **stable id**; `dismiss(id)` is idempotent. Mount one
`<ToastViewport toasts={toasts} onDismiss={dismiss} position={...} />`. Auto-dismiss runs **per
visible toast** (not in the store), so it **pauses on hover and focus-within** and resumes on the
remaining time; the close button and auto-dismiss share one once-only dismiss path; focus returns
to the pre-toast element on real removal (only when focus is loose + the target is still usable).
The viewport renders one **persistent, visually hidden `role="status"` polite live region**
(`aria-atomic`, `aria-relevant="additions text"`) that announces new toasts in **title→message→meta**
order — the visible toast is **not** a live region, and dismiss announces nothing. Variants
`info` (default) / `success` / `warning` / `danger` / `ink` are **visual only** (all polite — no
urgency/assertive API). `position`: `br` (default) / `bl` / `tr` / `tl` / `tc` / `bc`. `duration`:
omitted → default; finite → active, un-paused ms; `Infinity` → no auto-dismiss (close or
`dismiss(id)`). Not a dialog/alertdialog/focus-trap; appearance never moves focus; action + close
are in normal Tab order. forced-colors + reduced-motion recipes. No flip/clamp/portal, no
safe-area/mobile breakpoint; a bare `<Toast>` outside the viewport is a static visual card (no

### tooltip
Short, non-interactive description tied to a trigger (`role="tooltip"` + a stable

### popover
