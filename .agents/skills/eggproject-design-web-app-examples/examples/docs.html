Webhooks that don't lie.

How to subscribe to events from the EggProject platform, what payloads look like, and the small rules that keep your handler honest when the network gets weird.

v2.4 · Updated 12 May 2026 · ~ 6 min read Stable

Every meaningful state change in the portal — a new invoice, a comment, a project transition — emits a webhook. Subscribe to the events you care about; we'll POST a small JSON envelope to your URL within a second of the event happening on our side.

Webhooks are at-least-once. We will retry until your server returns a 2xx, so your handler must be idempotent. We give you everything you need to deduplicate.

Local dev: use the tunnel
Run egg tunnel start in your terminal to receive webhooks against a localhost URL — no ngrok required.

1. Subscribe to events

Create a webhook endpoint from the portal, or with the API. Each endpoint declares the events it wants. You can have up to 10 endpoints per workspace.

subscribe.sh bash 
1curl "https://api.egg.dev/v2/webhooks" \
2  -H "Authorization: Bearer $EGG_API_KEY" \
3  -H "Content-Type: application/json" \
4  -d '{
5    "url": "https://hooks.acme.io/egg",
6    "events": ["invoice.paid", "project.updated"],
7    "description": "Production · billing sync"
8  }'

The response includes a signing_secret. Store it somewhere safe — you'll need it to verify every incoming request.

2. The payload

Every webhook is wrapped in a standard envelope. The data field contains the resource as it exists right now — not a diff.

invoice.paid.json json 
{
  "id": "evt_01HRX9TWK4N9QV2GBTYE",
  "type": "invoice.paid",
  "created": 1747312842,
  "livemode": true,
  "data": {
    "id": "inv_2026_040",
    "number": "INV-2026-040",
    "client": "Aper",
    "amount": 840000,  // minor units, EUR
    "currency": "eur",
    "status": "paid",
    "paid_at": "2026-05-12T11:24:02Z"
  }
}

Every event has a unique id. Store it. If you see the same id twice, you have a duplicate — drop it and return 200 anyway.

3. Verify the signature

We sign every request with HMAC-SHA256 using the secret returned at endpoint creation. The signature is in the Egg-Signature header, alongside a timestamp.

verify.ts typescript 
import { createHmac, timingSafeEqual } from "node:crypto";

export function verifyEgg(rawBody: string, header: string, secret: string) {
  const [tsPart, sigPart] = header.split(",");
  const ts  = tsPart.replace("t=", "");
  const sig = sigPart.replace("v1=", "");

  // Reject anything older than 5 minutes — protects against replay.
  if (Math.abs(Date.now()/1000 - +ts) > 300) return false;

  const expected = createHmac("sha256", secret)
    .update(`${ts}.${rawBody}`)
    .digest("hex");

  return timingSafeEqual(Buffer.from(expected), Buffer.from(sig));
}

"If a webhook's signature doesn't verify, treat the request as if it never happened. Don't log the body, don't enqueue it, don't reply with a hint about what failed."

— Márton Kovács · engineering lead

4. Retries & failures

We retry any non-2xx response with exponential backoff for up to 72 hours. After that, the event is marked failed and surfaced in the portal so a human can investigate.

  • Return 2xx as soon as you've durably queued the event. Don't keep us waiting on downstream work.
  • If you need to back off, return 429 — we'll respect Retry-After.
  • Disabled endpoints stop retrying immediately. Re-enable them to drain the queue.
Don't reply with the resource state
A common bug: handlers reply 200 OK with a JSON body that hits a serializer error. The webhook is considered failed and gets retried. Reply with an empty body.
